## 权限模型

Identity 拥有角色、权限、角色关联、账号授权和授权审计五张表。Flyway V3 保留全部既有管理员的业务能力，回填 `OWNER`；新建账号默认为 `VIEWER`。空库初始化脚本只创建第一位超级管理员，不覆盖已有账号或口令。

| 角色 | 职责 |
| --- | --- |
| OWNER 超级管理员 | 全部15项权限，包括人员授权与治理 |
| OPERATOR 影院运营 | 影片、影厅、排片、优惠券、用户管理及订单查询 |
| FINANCE 财务人员 | 概览、订单查询、营收报表与导出权限 |
| VIEWER 只读人员 | 概览、影片、影厅、排片和优惠券的只读入口 |

多个角色取权限并集。营收导出权限已纳入模型，导出业务仍待 Fesod 子项实施。搜索状态与索引重建分别归属影片读取和写入权限。

JWT 只携带身份及密码版本；每次请求通过 Identity 的受内部密钥保护的 `/internal/accounts/access` 复核账号和当前权限。账号被停用、改密或撤权后，后续请求使用最新结果，不把权限长期写死在令牌中。其他业务应用每次只做一次合并复核请求；Identity 本身读取自己的数据库。复核不可用返回 HTTP 503 和 `Retry-After: 2`，不缓存放行、不清除客户端登录凭证。

Spring Security 对管理 URL 使用明确的域和读写策略，未知管理路由默认拒绝。前端每次进入管理路由时刷新当前权限，菜单、快捷入口、写操作和座位编辑入口据此显示；只读排片使用列表。权限不写入本地持久化，修改 localStorage 无法增加服务端授权。前端隐藏按钮只用于改善操作体验，实际权限由各域后端控制。

## 账号保护与审计

角色调整、冻结和删除使用同一份管理员行锁顺序，避免并发操作绕过最后一位账号保护。至少保留一位启用的超级管理员；不能修改当前登录账号自身角色。角色变更与审计写入处于同一本地事务，保存操作者、目标、前后角色和时间，不保存口令或令牌。其他旧有口令、冻结和删除保护继续生效。
