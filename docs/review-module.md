# 用户评价模块

更新日期：2026-10-20。评价通过普通业务接口完成，本次升级未新增 AI 工具或模型调用。

## 用户入口

- 订单列表和订单详情：满足条件显示“写评价”，已有评价显示“查看评价”；尚未散场时显示原因和预计开放时间。
- `/score/:movieId/:orderId`：发表、查看、修改及删除自己的评价。实际影片和场次以服务器返回的订单上下文为准，不信任路由中的影片编号。
- `/me/reviews`：分页查看自己的评价，支持修改、删除、查看订单和跳转影片。
- 影片详情：本店观众评价、独立的五分制均分和分布，按更新时间或评分排序、分页；游客可查看。

## 业务约定

1. 一单一评；订单必须属于当前用户，已支付（2）或旧版已完成（6），对应场次有效（1），且电影放映已经结束。
2. 已知影片时长时，开放时间为开场时间加影片时长，不包含影厅清场时间；未知时长时保守使用场次结束时间。资格由服务端统一判定。
3. 评分为整数 1～5，短评选填，最多 1024 个 Java/JavaScript 字符单元。服务端会去掉首尾空白。前后端均校验。
4. 评价与订单状态独立：发表、修改或删除评价均不改变订单状态，也不修改影片外部来源评分 `movie.score`。
5. 修改和删除必须携带当前版本；事务内锁定订单行，防止并发首次发表和旧窗口覆盖。首次发表使用 `expectedVersion: 0`，兼容旧版首次发表省略版本。
6. 已取消、退款或其他不再满足资格的评价保留在“我的评价”，标记未公开，可查看和删除，不能继续修改。公开列表和统计实时排除这些记录及非法评分、归属或影片不匹配的旧记录。
7. 公开昵称仅显示首字符和 `***`；不会公开他人的用户编号、订单编号或版本号。短评按文本转义渲染。本人在公开列表中可获得自己的编辑入口。
8. 无评价时详情接口返回成功且数据为 `null`；历史记录没有时间时显示“历史评价”，不伪造发表时间。没有本店评价时均分为 `null`。

## 接口

沿用统一 `R` 响应封装；用户端接口需 USER 登录。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/user/score/context/{orderId}` | 本人订单的编辑上下文、资格原因、开放时间及已有评价 |
| GET | `/api/user/score/info/{orderId}` | 本人订单的原始评价；没有评价返回 null |
| POST | `/api/user/score` | `{orderId, score, content, expectedVersion}`，首次发表或版本匹配的修改 |
| DELETE | `/api/user/score/{orderId}?version=...` | 按版本删除本人评价；已不存在时幂等成功 |
| GET | `/api/user/scores?page=1&limit=10` | 本人评价分页，含未公开历史记录 |
| GET | `/api/movie/{id}/reviews?page=1&limit=10&sort=newest` | 游客可用的影片评价及 summary |

`sort` 允许 `newest`、`highest`、`lowest`。`page` 为 1～10000，`limit` 为 1～50，查询使用绑定参数。summary 包含 count、保留一位小数的 average 和 1～5 分 distribution；仅对公开有效记录统计。

用户评价控制器的业务异常使用 HTTP 400/401/403/404/409 及对应业务码；Bean Validation 和公开接口仍沿用项目全局异常响应约定，调用方同时检查 `R.code`。页面在冲突时保留草稿，允许明确选择重新载入。

## 数据库升级

已有数据库需先执行 `src/main/resources/db/migrate/2026_10_20__review_module.sql`，再启动新版后端。本机开发库已执行。

迁移幂等新增：

- `score.create_time`、`score.update_time`：可空 DATETIME，旧数据保留空时间。
- `score.version`：非空 BIGINT，旧记录默认 1。
- `idx_score_movie_time(movie_id, update_time, id)`：评价查询索引。

保留原有 `order_id` 唯一约束。迁移同时修复旧逻辑提前评价后被改成 6 的未来有效场次订单，将其恢复为已支付 2，保留评价原文，使其继续遵循正常退票规则；散场前这些旧评价不会公开。其他旧版 6 状态保持兼容。

新库结构参考 `schema.sql` 和 `schema_new.sql` 已包含新字段。项目没有自动执行此迁移；部署到其他数据库仍需显式执行。
