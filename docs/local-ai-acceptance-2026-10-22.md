# 2026-10-22 本地 AI 客服验收记录

任务 1 已完成。本次使用现有本地单副本微服务环境，未连接云服务器，未进行云端容量或高可用验收。

入口：<http://localhost:8088/ai>。用户使用原有普通用户账号登录即可咨询和确认办理；测试账号已删除。

## 完成内容

1. 将工具调用的业务编号、参数和返回值按用户会话持久化，隐藏于前端消息列表，按字符预算回放给下一轮；订单状态、票价、余票、评价资格仍现查。
2. 新增 SSE 完成事件，先保存历史、收尾生成占用，再发送真实服务单快照；断连缺少完成事件时明确提示中断，前端不会把模型文字当作业务卡片。
3. 明确场次/座号的购买请求先精确定位票号，补齐情侣对，并复用实际票价和可售校验；撤销后可重新拟单。订单售后优先使用明确订单 ID，避免误用旧订单或截断长订单号。
4. 单一订单 ID、评分及引号内评论原文都明确的评价请求先实时校验拟单；含否定、多个候选或缺项时不自动猜测。
5. 新增本人会话的服务端停止接口，前端停止、新建、切换对话时释放原生成；停止结果写入历史，下一轮按最新问题继续，不自动补答已停止的问题。
6. 保留 URL 中的当前会话，刷新和返回聊天页可恢复；独立处理历史/服务单加载失败，避免旧响应把已办理服务单恢复成待确认。

所有服务单仍需用户点击“确认办理”才调用领域服务。支付与退款沿用项目的模拟业务。

客服验收覆盖：

1. 真实验证码、注册、普通用户登录。
2. 影片、详情、排期、座位、个人资料和订单页面。
3. 连续生成想看和资料修改两张确认单；确认前数据不变，重复确认幂等。
4. 查询座位后用下一句购买刚才座位，场次和座号正确；确认后才锁座下单。
5. 从服务单进入模拟支付，返回同一会话查实时支付状态，生成并确认退票单。
6. 撤销拟单不改变业务记录。
7. 撤销后重新生成购票单、确认下单，再生成并确认独立取消单。
8. 已散场付款订单生成评价单，确认前无评价，确认后评分和评论原文一致。
9. 首 token 前停止，随即在原会话成功发出新请求。
10. 刷新恢复指定会话及全部服务单，390px 移动端无横向溢出。

基础浏览器回归覆盖：公共页面、同组件电影 ID 切换刷新、榜单失败与重试、注册密码前端校验、管理员真实验证码登录、八个管理页面、营收 CSV 导出、可信/不可信来源的 CORS 检查。

## 原任务 2：云端计划已取消

用户后来已改为全部应用与新增中间件在本地单实例运行，保留千问 API 与阿里云 OSS；当前以后续 [本地实施计划](local-singleton-stack.md) 为准。下面仅保留原云端任务的历史边界，不再等待或申请云服务器配置。

云端高可用、高并发尚未部署或压测。收到服务器连接配置、CPU/内存、机器数量及流量目标后，再确认现有服务和数据布局，测量基线，实施扩容、故障恢复及容量验收。

特别是本地停止信号与最近座位补救仍有单 AI 实例语义，多副本需要跨实例停止协调和相应验证；单实例的 MySQL、Redis、Nacos 也不能仅靠增加业务副本获得基础设施故障切换。已有部署/限流配置须按云端实际资源与故障演练结果验收，不把本地通过当作生产容量承诺。
